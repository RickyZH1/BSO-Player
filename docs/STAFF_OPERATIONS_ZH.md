# 工作人员现场操作手册

8位Staff使用8个不同账号，全部可查看/处理六队所有业务。负责人是现场分工，后台不限制代办。每次写入会记录实际登录者；不要借用其他工作人员账号。

## 开赛前

1. 用Staff账号登录，进入总览，应见六队，人数7/7/7/7/7/8；未演练的正式库初始各500两。
2. 管理 → 集合、范围及联络：填开场集合地点、三场对阵与人员安排、安全范围、公开联络渠道。
3. 管理 → 地点线索编辑：填七项公开探索线索。只写模糊线索或NPC大致活动范围；精确位置写下方“工作人员规则与私密地点”。
4. 迅哥的学习来源可以公开；正式题目、答案写私密工作人员规则。
5. 打开原有目标照片检查现场仍有效。地图仅示意，不能替代园内标识。
6. 核对所有工作人员能登录、所有Team能同时多人登录；实物银票负责人准备核对纸表。

## 统一开场与放行

管理 → 阶段控制 → 统一开场 → 确认。

在关卡页选队伍与Focus Hunter → 进入关卡 → 登记开始挑战。双方按规定参与后，分别填写本队有效成绩，勾选完整参与，点击“计算奖励并核对”，确认金额后提交。

T6有8人不改变开场目标人数规则；目标成员/拍摄者由现场总控安排，余下人员遵守原规则旁观或协助。详细规则只在Staff的“查看私密工作人员规则”中读取。

三场对阵、六队开场完成后，管理 → 自由探索。若任一队未完成，服务器拒绝放行。放行后全部队伍同时获取第一层线索与照片墙；不按九宫格位置逐关解锁。

## 正式关卡成绩

1. 选正确队伍、关卡。
2. 开始前点“登记开始挑战”，确保服务器已记录。
3. 按现场规则操作；不能事后回填开始时间。
4. 完整参与后输入有效成绩。MINI BINGO输入三次最终落点，出界/无效选0；需要时输入累计作答秒数（按实际值向上取整到整秒，不得向下取整以获得边界奖励）。
5. 勾选完整参与，先让服务器算奖，核对后确认。
6. 零分也可完成六个现场关卡；弃权不能盖章。美食例外，必须全部验收。
7. 重复点确认不会多发奖励。玩家15秒内自动更新，回到网页也会主动刷新。

请把电子确认与实体银票发放视作一次业务：指定工作人员在纸质发票表勾选，网络重试时先核对流水，不能看到又成功一次就再次发实体银票。

## 照片审核

照片页按服务器完成提交的时间排序，时间在完整上传后确认送审时记录。仅点击“选择照片”或拿到上传地址不占先后名额。

1. “查看证明照片”获取60秒有效的私密签名链接。核对目标地点及本队成员/队号。
2. 点审核 → 通过，或驳回并写清原因。玩家被驳回后可以上传新版本。
3. 同队同目标只能有一份有效记录；不会按提交次数加分。
4. 后提交照片先通过时可结基础奖，但只要更早提交仍pending，首发额外奖保持未决。
5. 更早照片全部裁决后，系统自动确定该图最早有效提交。首发额外奖励仅多一份，不把总奖再叠加基础奖。
6. 误审：审核已通过记录 → 驳回/撤销，写原因；若原驳回错了，可改通过并说明。若该队同图已有另一有效版本，先撤销错误版本，再通过正确版本。
7. 首发归属变化、照片数量不足五张、相关Bingo资格失效都会自动生成冲正/更正流水并留痕。
8. 已有五张完成后，第六到第十一张仍可提交、审核、赚银票。

上传中断的玩家可以在同图历史里点“重试确认上传”。如果文件没到服务器或预留超过10分钟，会明确报错；重新选择照片再传。不应把未确认送审的预留当作首发材料。

## 美食任务

关卡页下方有六队各自清单。Seven负责现场组织，但任意Staff可代办：

- 解锁：确认队伍到场领任务，点“解锁本队清单”，只有该队玩家可读。
- 门店关闭/售罄：由Seven现场决定替代方案，在“修改替代方案”填写完整清单及原因。本队玩家看到替代后内容，其他队看不到。
- 验收：可当面看手机照片，无强制Web上传。确认所有门店及品尝要求后，在上方选Team, the eater，登记开始/填完成成绩并核对奖励。
- 未完全完成不可以给部分奖励或盖章；不能用“0分完成”绕过美食验收。

## First Bingo与Full House

玩家达标后自己申报。工作人员不能通过伪造队号替玩家倒填时间。

Bingo页显示提交时间、资格审核状态及服务器计算结果。可以批准或驳回，驳回必填原因。逆序批准不会改变排名；如果更早申请仍未决，后面的“审核通过、奖励0”表示等待顺位，不是出错。全部更早申请裁决后自动结算。

Full House是独立申请，不能把First Bingo申请当成Full House。更正某格导致资格失效，会撤销相应申报并冲正奖励；恢复资格后需队伍在截止前重新申请。系统不自动倒填申报时间。

玩家从不看到其他队排序或身份，也没有队伍排行榜。

## 清盘

1. 管理 → 清盘提醒，填写上海时间最终截止，至少比服务器当前时间晚15分钟。
2. 发布后不能提前，允许在原截止到达前合理延后，但新的通知仍须至少提前15分钟。
3. 公告自动发布。不能通过手动把阶段设CLOSED提前结束。
4. 一到服务器截止，即使尚未点击CLOSED，新照片送审、Bingo申请、新任务开局也被拒绝。
5. 此前已登记开始的任务仍可确认结算银票，但截止后确认的完成不计Bingo。
6. 截止前送审照片可以事后审奖。若照片第五张在截止后才获准，完成任务但不允许倒造新的截止前Bingo资格/申报。
7. 截止后进入“比赛已截止”，处理所有pending材料、对账、导出，再选“已归档”。存在待审核材料时不能归档。
8. 归档后业务只读。没有“一键重开比赛”，避免意外破坏公平性；行政争议应保留日志由主办方决定后续处理。

## 更正、审计与导出

- 关卡成绩错误：进入已完成关卡，输入修正成绩与必填原因，服务器追加差额流水。时间资格沿用原已验证完成，不允许更正时回填过去时间。
- 完成判定错误：点击“撤销任务完成与奖励”，说明原因；相关Bingo奖重新计算。
- 照片/Bingo错审：在对应审核页更正，系统会重新分配竞争奖励。不要只手工加减银票而忘记修正完成状态。
- 纯实物对账差额：管理 → 银票更正，填正/负10两整数倍、明确原因。原流水保留；需要反向纠错就再次追加相反金额并引用原流水ID，不能删除历史。
- 总览：导出六队成绩CSV、全部银票流水CSV。
- 管理：最近200条审计及其CSV。完整审计由项目拥有者在Supabase Table Editor → audit_events导出，不把CSV公开上传。

## 网络应急

网页报“未完成”或“未同步”时先核对结果，避免再次发实体银票。断网不自动写入本地假成绩；无法联网就用纸卡与实物银票。

准备纸卡、每队任务记录表、逐图首发顺序表、照片原始消息/本机记录。人工备案写队伍、任务、现场时间、审核人、有效性及发票。恢复网络后由总控按证据处理纠纷并记录更正原因；系统刻意不允许普通表单随意回填申报时间。

结束后按组织者的照片告知约定清理证据：先导出必要审计，再用Supabase Storage后台删除到期文件，勿把证据bucket设public以便“批量下载”。
